# Warren

An agent-based predator–prey ecosystem in Unity, and a survival game played from inside it.

The simulation came first: plants, rabbits, deer, foxes and wolves, each an autonomous agent with its own energy budget, senses and decision state machine. The game layer came second — you possess a single rabbit and try to keep your warren alive for seven nights. Crucially, possession does not give you a parallel implementation. The rabbit you control is the same `Rabbit` class the AI drives, bound by the same movement speed, energy drain and reproduction rules as every other animal in the world.

The engineering problem this project is really about: **adding a game on top of a simulation without the simulation knowing the game exists.**

## Running it

1. Open the project folder with Unity Hub → **Add project from disk**.
2. Wait for compilation, then run **EcoSim → Build Everything** from the top menu bar.
3. Press **Play**, then **Start**.

Step 2 is not optional, and it is the point. No prefabs, scenes, materials, meshes or textures are committed to this repository — all of them are generated by [`EcoSimProjectBuilder.cs`](Assets/Scripts/Editor/EcoSimProjectBuilder.cs) (718 lines), so the entire project rebuilds deterministically from source. What you clone is code and nothing else.

## Architecture

Everything lives under the `ThodupunuriAnshul.EcoSim` namespace, with sub-namespaces mirroring the folder layout. Dependencies point one way only:

```
Core  ←  Agents (+ Habitat)  ←  Player  ←  Game  ←  UI
```

```
Assets/Scripts/
├── Core/        SimEnums, IEdible, AnimalStats, SimEntity, SimulationManager
├── Agents/      Plant, Animal, Herbivore, Carnivore, Rabbit, Deer, Fox, Wolf
├── Habitat/     Burrow, DayNightCycle
├── Player/      PlayerController, PlayerAbilities, AbilityType, FollowCamera
├── Game/        GameManager, GameState, GameSettings, RunRecord
├── UI/          GameHUD, PopulationHUD, CameraController
├── Utilities/   SimUtils, InputHelper
└── Editor/      EcoSimProjectBuilder
```

**Agents never reference the game layer.** They raise C# events — `SimEntity.Died`, `Rabbit.JoinedWarren`, `DayNightCycle.DayStarted` — and `GameManager` subscribes. This is why the original sandbox scene still runs unmodified against the same agent code that powers the game.

Diagrams (Mermaid sources and rendered PNGs) are in [`Docs/diagrams/`](Docs/diagrams/): class diagram, decision state machine, food web, game state machine, game loop, and the layer architecture.

## Turning a simulation into a game

The simulation existed before the game did. These are the changes that made a player fit inside it, and the reasoning behind each:

| Change | Where | Why |
|---|---|---|
| **Possession API** — the same `Animal` is driven by its AI or by player input | `Animal.SetPlayerControlled`, `SetMoveInput`, `TryEatNearby`, `TryMateNearby`, `CancelBusyAction` | The player obeys the same speed, energy and coroutine rules as every other rabbit. No second implementation to keep in sync. |
| `SenseFood()` split into `FindFood(range)` + `SenseFood()` | `Animal`, `Herbivore`, `Carnivore` | One spatial query serves both the AI's senses and the player's shorter reach |
| `IsReadyToMate` split out into `MeetsMatingRequirements` | `Animal` | AI and player share one mating rule rather than two that can drift |
| Herd alarm lifted from `Deer` up to `Herbivore`, with a generic `AlertNearby<T>` | `Herbivore`, `Deer` | Rabbits can now receive alarms — the player's **Thump** reuses the existing deer alarm instead of adding a parallel mechanism |
| `IsHidden` → `CanBeEaten` returns false | `Herbivore`, `Rabbit` | Burrows work without predators needing to know burrows exist |
| `SpawnAdult`, `SpawnGroupAtArenaEdge` | `SimulationManager` | Removed duplicated spawn code; now also serves night-time arrivals |
| World modifiers `PredatorSenseMultiplier`, `PredatorSpeedMultiplier` | `SimulationManager`, `Carnivore` | Difficulty curve without mutating per-species stats |
| `Died` event | `SimEntity` | The game reacts to deaths without agents knowing a game is listening |
| Scene builder split into `CreateBaseScene` + `CreateSandboxScene` / `CreateGameScene` | `EcoSimProjectBuilder` | Shared setup written once |

### Game systems

| Class | Role |
|---|---|
| `GameManager` (singleton) | Run state machine (Title / Playing / Paused / GameOver / Victory), lineage transfer on death, difficulty, ability unlocks, scoring, best run |
| `PlayerController` | Input → commands for the possessed rabbit; stamina, threat awareness, world marker |
| `PlayerAbilities` | Unlock gating and cooldowns for Thump, Dig Burrow, Swift Feet |
| `DayNightCycle` | Day counter, progressively longer nights, lighting, `DayStarted` / `NightStarted` events |
| `Burrow` | Safe zone with a static registry and spatial queries |
| `FollowCamera` | Third-person orbit camera; slow overview orbit on menus |
| `GameHUD` | One screen per game state, drawn with OnGUI against a 900px virtual canvas |
| `DifficultySettings`, `ProgressionSettings`, `RunRecord` | `[Serializable]` balancing data, tunable in the Inspector; best run persisted via `PlayerPrefs` + `JsonUtility` |
